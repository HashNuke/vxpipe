# Google interruption control

- Scope: audit engine-requested Google STS response cancellation against the selected Live VAD profiles, with fake-wire failure/isolation proof. This is not a hosted interoperability claim.
- Official [Live WebSocket reference](https://ai.google.dev/api/live) states `realtimeInput.activityStart` and `activityEnd` can be sent only with automatic activity detection disabled. Its `interrupted` flag is server output reporting a client-message interruption, not a standalone client cancel command. The [capabilities guide](https://ai.google.dev/gemini-api/docs/live-api/capabilities) describes automatic VAD barge-in from real user audio, while manual `activityEnd` closes a user activity. No supported standalone cancel command was found in the inspected profile; synthesizing activity to force cancellation would invent caller input.
- Red proof: `mix test test/vxpipe/providers/google/sts_session_test.exs:389 --seed 0` returned 1 test, 1 expected failure. Provider-mode `STSSession.interrupt/2` returned `:ok` and sent a client control instead of failing the allocation; automatic VAD is enabled in this profile.
- Decision: fail the affected allocation explicitly for engine-requested interruption of the current Google response; preserve server-origin interruption handling and local response-specific discard of an older response that is no longer on the wire. External mode also must not use idle `activityEnd` as output cancellation. This avoids falsely claiming provider history was truncated.
- Follow-up red: after removing the invalid command, the 106-test Google session/controller group exposed three server-origin interruption failures (a subsequent genuine reply could not emit audio). The capability was echoing an interrupt back to the provider while handling the provider's own `interrupted` event, and legacy provider state could leave the shared output slot without a terminal. A separate focused red reproduced a late legacy grant after the provider retired the interrupted turn being silently ignored, leaving the channel slot occupied.
- Repair: capability distinguishes provider-reported interruption from an engine cancellation request, so the server event never echoes a wire cancel. The legacy provider emits the exact output terminal immediately when no credit is outstanding, or after that credit resolves; the opted-in response owner already drains its discarded response after credit. It retains the late-audio fence until genuine caller continuation, then reopens for the new reply. A grant for a retired legacy turn now fails the allocation rather than stranding the slot. There is no new timeout or history replay.
- Focused evidence (Call Engine child, seed 0): 112 Google session and actual-capability controller tests pass, including provider/external/opted-in manual interruption, server interruption with outstanding legacy and opted-in credits, pre-admission continuation, late-grant failure, and local old-text isolation. This is fake-wire evidence; cross-origin unlabelled output after interruption and hosted history reconciliation remain open.
- Independent Astra xhigh review found a delayed-credit overlap that the initial 112 tests missed: A remains in `state.output` until its outstanding PCM credit returns; B model output arriving after a genuine B caller start is dropped or published under A. A new focused test sends B text/audio and `generationComplete` before acknowledging A's credit. The red fails deterministically because B's `output_transcript` appears before B is granted (1 test, 1 failure at line 551, seed 0). The test then requires A settlement and B's own text, PCM, terminal and settlement.
- The repaired legacy output assembler recognizes an interrupted A record while B's caller reference is current, retaining B's text and PCM in the existing bounded pre-admission buffers and B's generation completion independently. The focused reproduction passes 1/0. The Google codec/session/controller and shared context/origin group passes 196/0, seed 0. This assumes a genuine distinguishable B caller/model boundary; arbitrary unlabelled wire output after that boundary remains a separate milestone proof.
- A further focused fence test now covers B speaking before interrupted A's model completion. Text and PCM were already dropped, but a `generationComplete` was incorrectly retained as B's pending generation. The 1-test red failed on `generation_pending_done? == true`; the output assembler now ignores generation completion while the post-interruption fence is active. The focused test passes. Its provider-state assertions use a subsequent input-transcript event as a processing barrier; a raw `:sys.get_state` request from the test is not a reliable ordering barrier for a message sent by the fake socket process.
- Astra xhigh review found the other legacy A/B branch: A had already emitted its interrupted terminal with no outstanding credit but had not settled. B's text was buffered under a new genuine caller; settling A unconditionally cleared `output_text`. A focused session test failed because B's `output_transcript` never arrived after B's grant. Settlement now clears text only when the settled turn is still the current input turn. The reproduction passes 1/0, and the Google codec/session/controller plus shared context/origin group passes 198/0, seed 0. No hosted calls or history-reconciliation claim.
- Independent Astra xhigh re-review of the repaired diff found no further actionable defect; it independently checked both the settlement and pre-model-boundary fence branches. The separate parent gate for arbitrary unlabelled post-interruption wire attribution stays open.
