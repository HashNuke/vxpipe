# STS room input checkpoint

## Scope

Continue directly after the committed STS runtime checkpoint. Connect the
independent microphone ingress to the agent-owned allocation and prove a real
compiled room turn using Morse audio. No delegated work or hosted API calls.

## Red/green evidence and findings

  expected failure because `ConnectionAttachment` had no STS input handle.
- Implemented a connection-bound lookup that survives asynchronous allocation
  preparation, an ingress beneath the STS tree, grouped policy registration,
  and explicit STS readiness demand. Input remains closed until readiness.
- The next real-room run produced reply audio but failed caller transcript
  publication. `TranscriptRouter` expects the source's transcript policy

  and exactly one agent transcript after explicit sink playback settlement.
  This is embedded transport coverage, not WebRTC/telephony conversion proof.
- Added failing checks for missing STS ingress readiness evidence, monitor or
  foreign-source allocation, duplicate admission during entry preparation, and
  installation with an already attached source. All four initially failed for

  rebind during startup installation. The focused room/readiness/publication
  group passed 57 tests with seed 0.
- A broader child run exposed old closed-demand assertions and a unit test that
  treated an unbound capability as ready. Updated these for explicit STS demand

- Receiver regression initially failed because raw `push_audio` could bypass

- Self-review found that using the current transcript interval at settlement

## Decisions and remaining work

- The input process is dynamically supervised beneath the agent tree once the
  validated provider descriptor is ready; it monitors the exact source and
  capability. The capability also monitors ingress loss.
- Hold/release rotates an input epoch; queued or already-delivered old-epoch
  audio cannot become current on release. Receiver checks policy revision,
  source identity and age before invoking the provider.
- Transport conversion still needs implementation in Gateway. Connections
  that omit selected STS preparation must fail readiness, not silently start a
  call without microphone input. Three transcript modes, real-call load and
  remaining lifecycle/tool acceptance are still open.
- Next Gateway boundaries identified: WebRTC `SpeechInput.prepare/3` and
  `IncomingAudio.deliver_to_inputs/3`; telephony `MediaSession.normalizer/2` and
  `IncomingAudio.deliver/5`; shared `Media.ConnectionReadiness`. Each currently
  prepares/delivers only human STT. Reuse conversion implementations with a
  separate STS consumer state, test each independently, then add real three-mode
  room/load coverage. Do not treat the entry-install unit scenario as a full
  scheduler-controlled early-attachment transport test.
