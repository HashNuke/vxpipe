# Run QA release

## Scope and decisions

- The user requested a real production release in the sibling `qa` worktree,
  with `APP_HOST=vitrum.vxpipe.com`, no Storybook and forced HTTPS. This is a local
  release checkpoint; it does not complete the container-delivery milestone.
- Added the named `vxpipe` umbrella release, rooted at `vxpipe_console`. Its
  application dependencies include the gateway, engine and persistence apps.
- Ran setup, built production assets and assembled the release. The `vxpipe-qa`
  user service runs migrations using release `eval` before starting the app.
  It is enabled at boot with user lingering. The release itself does not use Mix.
- Added requested QA settings by write-only append to the ignored `.env` file.
  No environment-file contents were inspected. The service manager loads the
  runtime environment; no credentials or generated artifacts belong in Git.
- The `vxpipe-qa-proxy` system service runs Caddy with automatic HTTPS and proxies
  to loopback port 4001. Added TCP 80/443 to the existing attached Hetzner firewall
  and the host firewall, preserving existing rules. Initial ACME attempts failed
  while these ports were blocked; HTTPS succeeded after both firewalls allowed them.
- Replaced the nonstandard `AWS_ENDPOINT` setting with `AWS_ENDPOINT_URL_S3`,
  falling back to `AWS_ENDPOINT_URL` when absent or blank. An invalid selected
  endpoint fails safely instead of falling back. No compatibility alias remains.
  The existing S3 client already supports path-style R2 access and region `auto`.
- Container migration recommendation: package a small `bin/migrate` wrapper
  around Ecto's release migration API. Run it before application startup (or as a
  deployment pre-deploy command), against an existing database. Current Docker
  documentation references this command without shipping it; that remains part
  of container delivery, not a completed feature in this checkpoint.

## Verification

- Focused endpoint red phase: 8 tests, 5 expected failures before runtime wiring.
  Green phase: 8 tests, 0 failures. Coverage includes development/production
  destinations, precedence, blank fallback, invalid URL redaction and removed
  endpoint isolation. Production fixtures use a public hostname because production
  OAuth configuration rejects localhost; development fixtures use loopback.
- Production assets and initial release assembly passed. The initial service
  migrated successfully and served `/healthz`. Public HTTP redirected with 308 to
  HTTPS; HTTPS returned 200 and `ok`.
- Initial browser inspection reached `/auth/setup` with the public HTTPS origin
  prefilled and no browser errors. No setup form was submitted.
- Reassembled the release after the endpoint change and restarted it through the
  service manager. Migrations reported already up; both services are active. The
  rebuilt release contains no Mix application and includes all 57 source
  migration files. HTTP still returns 308 to HTTPS,
  and HTTPS `/healthz` returns 200. Rendered browser checks at 1440×900 and 390×844
  show the setup form and correct origin without browser errors.
- The service's migration expression pattern-matches success so a returned
  migration startup error also prevents application startup.
- Persistence runtime isolation: 2 tests, 0 failures. Changed documentation has
  no missing relative link targets.
- Formatting, warnings-as-errors compilation, strict Credo and unused-lock checks
  passed. The first umbrella test run (seed 50212) hit an intermittent
  `STSTransferRoomTest` assertion: `push_text/2` returned `{:error, :held}` after
  the failed-transfer event. The isolated test passed, the six-test file passed
  with seed 50212, and the full call-engine suite then passed with that seed:
  2,431 tests, 0 failures, 100 excluded. No speech/transfer code was changed.
- The initial umbrella run finished with 5,216 tests, 1 failure and 376 excluded;
  every other application passed, including Gateway (876), Persistence (501) and
  Console (554). Together with the full call-engine recheck above, every
  application's suite passed on this source. The initial umbrella command exited
  2; the call-engine recheck exited 0. The unused-lock check ran separately and passed.
- Actual R2 object access and provider-backed calls have not been verified.
