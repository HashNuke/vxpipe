# Call restart

## Goal

Keep terminal call state in its existing metadata position and let the user start a clean next call from the same console.

## Decisions

- Terminal and failed calls retain a `Call` action above the state and duration line.
- Starting the next call replaces the client snapshot instead of merging it, so terminal notices and run data cannot leak into the next run.
- The console remounts its workspace after a successful restart, restoring Conversation, default filters, collapsed disclosures, an empty composer, and the default participant selection.
- Preserve the completed transcript until the user explicitly starts the next call.

## Evidence

- Red: the lifecycle test could not find a `Call` action after leaving.
- Green: the focused console suite passes 19 tests; all 24 frontend tests and `npm run check` pass.
- Browser: inspected the ended story at 1280×900. It shows `Call` above `Call ended · 02:14`; after activation it shows `Leave call` above `Connected · 02:14`, Conversation is active, Logs is disabled, the terminal notice is gone, and the composer is enabled.
