# Tenant MCP integrations

- User asked for the workflow and implementation direction for functional third-party MCPs: tenant Services only, stored credentials, finite presets plus user-defined servers, CIMD/DCR/anonymous support. Worktree started clean at `56b0be64`.
- Inspected the existing Services form/catalog, provider credential boundaries, remote MCP configuration/catalog/runtime, ExMCP authentication APIs and installed authorization helpers. Existing runtime supports static bearer/custom headers/anonymous calls, but the product adapter has no durable outbound OAuth flow. Application-scope fallback exists in both IntegrationCatalog and ConfiguredNames and conflicts with the new tenant-only requirement.
- Checked the approved MCP 2025-11-25 authorization profile and primary Cal.com/Google documentation. CIMD/DCR are OAuth registration mechanisms; configured pre-registration takes priority. Cal.com documents both automatic paths. Google's official Calendar endpoint is Developer Preview and its current setup requires a client ID/secret, so a manual OAuth client path is needed. No live authentication, account connection or tool invocation was performed.
- Used Impeccable's shape reference and existing PRODUCT.md/DESIGN.md context for a compact Services workflow proposal. The existing session's design context was not rerun. No UI was edited, rendered or claimed reviewed in this research turn.
- Recorded the proposal in `docs/tenant-mcp-integrations.md`, including ownership, preset/custom flow, token lifecycle, runtime reuse, explicit agent tool names, implementation slices and acceptance checks. The proposal does not alter backend behavior, implement a callback, or move existing HTTP endpoints.
- Important implementation constraints: preserve full MCP endpoint paths; separate normal token refresh from pinned authorization generation; coordinate rotation across nodes; do not reuse Google AI credentials for Calendar; extend credential encryption/rotation with MCP identity binding rather than pretending the existing provider cipher is generic.
- Verification: read-only code/source review and documentation checks only. No Mix tests or browser tests are warranted for this proposal; no code, secrets or runtime settings changed. Work is uncommitted.
