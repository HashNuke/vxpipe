# VAD barge-in UI

## Scope and decisions

The shared latency panel now puts the user's two primary measurements in the
collapsed turn rows: end-of-turn detection (speech end to the STT turn-end signal)
and barge-in stop delay (human onset to acknowledged server egress stop). Dispatch,
response text and first audio remain supplementary expanded evidence. The panel
and each turn remain collapsed by default, with expand controls on the right.

The optional barge_in API field is parsed into bounded typed evidence; legacy
absent/nil data stays unavailable. The parser checks exact keys, identity bounds,
numeric bounds, fixed boundary/reason enums, timing order and stop-minus-onset
arithmetic. It permits confirmation after stop: confirmation is not the duration
baseline. Missing and ambiguous evidence have explicit reasons rather than zero.

Expanded barge-in evidence names the interrupted agent and original response's
human, output, connection and turn. It distinguishes that output from the newly
interrupting human's turn. It labels the server acknowledgement honestly and notes
that already-buffered remote audio can continue. All visible timings use ms.
Storybook covers available, ambiguous, missing stop acknowledgement and late
confirmation, in standalone shared and admin call-detail hosts. Synthetic fixture
identities were aligned with the existing admin participants after visual review.

## Review correction: positive sub-millisecond evidence

Review reproduced a precision bug: 100 µs of positive uncertainty was displayed as
0 ms. Added the exact backend-style fixture (20,000 µs onset, 35,000 µs stop,
15,000 µs duration and 100 µs uncertainty), plus summary checks for 1/100/999 µs,
exact zero, nil and integer-millisecond values. Before the fix, 4 of 37 focused
component tests failed for the expected rounding error. The formatter now shows
`<1 ms` for positive values below 1,000 µs, preserving `0 ms`, `Unavailable` and
existing integer-ms formatting. All 37 component tests pass afterward.

A bounded Chromium pass rendered the real BargeInEvidence/BargeInSummary components
