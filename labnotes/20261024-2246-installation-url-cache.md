# Installation URL cache

- User approved ETS-backed caching behind `InstallationSettings.public_url/0`. Preserve the existing uncommitted Installation URL backend work; no commit requested.
- Design: Identity owns the cache abstraction; Persistence supervises its named owner and loader task supervisor after Repo. Runtime injects the optional cache name alongside the installation repository. Embedded callers without a cache retain the direct-read path.
- A protected ETS table serves reads. A single bounded asynchronous load coalesces misses; successful local setup/settings writes invalidate after the repository operation returns, discard older in-flight loads, and warm from the database. Never publish a returned write value before an independent read can observe it.
- Defaults: refresh/expiry 30 seconds, failed-load retry 1 second, loader timeout 2 seconds, bounded waiting callers. Errors are distinct from a successfully cached unconfigured URL. Expired data is not served during an outage. Separate instances sharing the database converge on refresh; no distributed notification dependency.
- Tests first: fast repeated/nil reads, concurrent misses, expiry/failure/recovery, periodic refresh of two instances, invalidation races and bounded loading; then real-store setup/save integration and runtime composition.

## Implementation evidence

- Initial six cache tests failed because the module did not exist, then passed with ETS and coordinated asynchronous loads. An additional owner-crash test exposed a surviving `async_nolink` task. Switched to supervised linked tasks with exit trapping; the eight focused cache tests now pass, including task-crash recovery. No sleeps are used for synchronization; timer/clock seams and monitors make failure/expiry checks deterministic.
- Two real-store integration tests initially failed because `public_url/0` bypassed the cache. After wiring optional cache reads and successful-write invalidation, both pass. They cover setup from a cached nil value, saved changes, stale-write rejection and committed saves during local cache unavailability.
- Default settings/editor reads stay authoritative; only the public-origin accessor is memoized. Existing embedded callers remain compatible without configuring a cache. No Redis/package dependencies added.
- Root format check, compile with warnings as errors, strict Credo, and unused-dependency check passed. The Identity app has no local formatter configuration, so changed Identity/Persistence files were formatted and checked explicitly from the umbrella root in addition to the required root check. `git diff --check` passed.

The initial telemetry probe used the wrong prefix; correcting it to `[:vxpipe, :persistence, :repo, :query]` made the observation work. No data or URLs were logged or changed.
