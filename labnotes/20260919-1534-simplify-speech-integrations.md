## Findings and decisions

- Current STT/TTS behaviours describe a provider codec plus separately configured transport.
  Native Morse encodes/decodes JSON solely to fit that interface. TTS capability code owns
  provider speech IDs, speak/flush ordering and cumulative interruption offsets.
- A smaller semantic session interface can hide those details while preserving the current
  capability processes for room policy, attribution, queuing, playout and lifecycle.
- Configuration, readiness, usage and cache metadata must remain explicit. The current optional
  readiness callback actually fails readiness when missing; one typed ready event removes that
  ambiguity. Readiness must distinguish initialization from provider acknowledgement.
- STT policy preparation is a real lifecycle boundary: replacement sessions cannot publish
  buffered results into a new permission interval. The migration includes asynchronous startup,
  early-event ordering, cancellation and adoption checks, not only decoder replacement.
- Provider submission and generation are separate from admission and playback. Retain usage
  after accepted Speak/failed Flush, discard stale audio without inventing zero usage, and settle
  once. Keep one acknowledged output write and responsive cancel/close under backpressure.
- Official provider comparison exposed manual versus automatic STT endpoints, segment commits
  versus user turns, Rime batch/flush coalescing, context cancellation, explicit packet/container
  formats and request-based TTS. Gemini Live is a model/conversation session, not automatically
  standalone STT/TTS. New hosted providers and external endpointing remain outside implementation.
- Chose eight checkpoints: standalone Morse STT; room STT; Deepgram STT; standalone Morse TTS;
  room/opening TTS; Deepgram TTS; independent contract examples/guide; final configuration and
  all-consumer acceptance. Temporary bridges are removed with their last built-in migration.
- Place the milestone immediately before delivery/retention without renaming existing files.
  All implementation boxes stay unchecked. Delivery now links the planned prerequisite; its
  authorization hold remains unchanged.

## Local specification review

Reviewed contract/dependency order separately from implementation progress. Corrected the initial
sketch to cover segment/turn boundaries, provider batch/request completion, upstream deduplication
versus local sequence stamping, admission/submission accounting and local/remote cancellation.
Reviewed format compatibility, current credential inheritance, independent opening/cache paths,
source-restoration/private-briefing consumers, supervision ownership and tagged test lanes.
No subagents were used and no independent approval is claimed.

Final review caught interruption during sink drain after generation completion. A provider
cannot infer locally played offsets from generated bytes. The shared output/session ledger now
supplies request-relative and session-total confirmed playback to the cancel operation; the
adapter selects/encodes its wire coordinate system. The milestone explicitly tests a subsequent
request's offsets and avoids a second generation-terminal/usage settlement for completed work.
