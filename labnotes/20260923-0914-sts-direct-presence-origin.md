# STS direct presence origin

Independent Astra xhigh review of `0f4ba651` reproduced a separate direct-input origin leak in external and hybrid modes. Using the existing `SpeechContextProbe` fixture, it applied an unrestricted snapshot with caller and agent present, pushed direct audio to capture a response context, removed the selected agent in revision 1, restored it in revision 2, then pushed fresh audio or emitted a response against the old context. Fresh audio reused the old context, and the delayed old response was granted. Four bounded probes failed on both seeds; pre-guard in-memory code discarded the late old response. No files were edited by the reviewer or hosted service used.

The room-ingress guard from `0f4ba651` must stay: direct input should not enter a room hold on policy rotation. The `ResponseOrigins` fingerprint currently uses caller input/output intervals but no selected-agent presence generation, so after leave/regrant its identity can be identical to the old one. The approved focused repair is to bind direct origin validity to a selected-agent policy interval that changes on presence transitions, and reject input while that agent is absent. Add project-owned reds before implementation and retain room-origin retirement tests.

Owning red: four generated tests in `sts_capability_origins_test.exs` (external/hybrid absent-agent input plus old-response grant) failed 4/4, seed 0. `push_audio` returned `:ok` while the agent was absent; after regrant, `{:emit_response, old_context, turn, 1}` produced `context_output_granted` rather than `context_response_discarded`. The local test uses the exact `SpeechContextProbe` allocation and snapshot sequence from the review, not a fabricated fingerprint.

Green: `ResponseOrigins.fingerprint/1` rejects a snapshot lacking caller or selected agent and includes the selected agent's audio-input policy interval in the fingerprint. The interval changes across that agent's presence loss/regrant even when caller intervals do not. This keeps the direct capability unheld, produces a fresh context after regrant, and discards late old-context responses. The four tests pass; the adjacent six-file origins/room/capability group passes 135/0 on seeds 0 and 1. No hosted service used. Astra xhigh re-review and post-commit root gates remain pending.

The normative STS response-context paragraph in `docs/speech-provider-contract.md` now names selected-agent presence generation and input-time participant presence, rather than implying caller intervals alone define the origin. This does not change the legacy non-opted callback contract or claim hosted Google association.
